# Prototype: the gtr.json → go bridge

Date: 2026-10-09. Go 1.24.7, linux/amd64.

Question: can a project without a hand-written `go.mod` import gtr packages
by short names (`import "orm"`, `import "orm-mysql"`) and build with plain
`go`, if gtr itself generates a `go.mod` with `replace` directives pointing to local directories?

Answer: yes. The resulting decisions are recorded in [ADR-0001](../../adr/0001-module-model.md)
and [ADR-0002](../../adr/0002-import-paths-and-names.md).

## How to run

```bash
bash run.sh                       # in a temporary directory
KEEP=./tree bash run.sh           # keep the tree for inspection
bash tidy.sh ./tree               # check the canonical go.mod format
```

The environment gtr runs go with: `GOPROXY=off GOFLAGS=-mod=mod GOWORK=off`.

## What was tested

| # | Check | Result |
|---|---|---|
| 1 | `replace` to a package directory without `go.mod` | **Error**: `reading gtr_modules/orm/go.mod: no such file`. A `replace` target directory must contain a `go.mod` |
| 2 | gtr generates a `go.mod` in every package directory | `go build`, `go test`, `go vet` pass |
| 3 | Short paths `orm`, `orm/schema`, `orm-mysql` | Work; the package inside is `package mysql`, called as `mysql.Driver()` |
| 4 | External Go module (`github.com/go-sql-driver/mysql`) as a local directory | Works with `GOPROXY=off`; gtr downloads it, not go |
| 5 | `go list -deps` (what gopls is built on) | Sees all packages with their on-disk paths; gopls was not available in the prototype environment, check it in an IDE separately |
| 6 | Versions in the binary (`go version -m`) | Visible: `orm v0.1.0 => ./gtr_modules/orm` |
| 7 | `go.sum` | Not needed: go does not create it for directory `replace`s |
| 8 | `go mod tidy` on an arbitrary go.mod | Rewrites the file (moves indirect dependencies into a separate block) |
| 9 | `go mod tidy` on the canonical format (see below) | Changes nothing, so tidy does not "break" the hash |
| 10 | Absolute path in `replace` (straight to `~/.gtr/store`) | Works |
| 11 | A package named like a stdlib package (`errors`) | **Error** `ambiguous import: found package errors in multiple modules` |
| 12 | Package in `require` but missing from `replace` | Confusing go error: `malformed module path "orm-mysql": missing dot in first path element` |
| 13 | `go get` inside the gtr environment | `module lookup disabled by GOPROXY=off`: dependencies must be added through gtr |

## Canonical format of the generated go.mod

`go mod tidy` leaves it unchanged:

```
// generated by gtr from gtr.json — edit gtr.json or run `gtr sync`
// gtr:hash sha256:<hash of the content below these lines>

module app

go 1.22

require (
	orm v0.1.0
	orm-mysql v0.1.0
)

require github.com/go-sql-driver/mysql v1.10.0 // indirect

replace orm => ./gtr_modules/orm

replace orm-mysql => ./gtr_modules/orm-mysql

replace github.com/go-sql-driver/mysql => ./gtr_modules/.go/github.com/go-sql-driver/mysql@v1.10.0
```

Rules: direct dependencies go in the first `require` block, transitive ones in the second
with `// indirect`, each `replace` on its own line, everything sorted.
