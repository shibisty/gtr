# 10. CI

## GitHub Actions

```bash
gtr init --ci          # writes .github/workflows/ci.yml
```

The generated workflow runs on Linux, Windows and macOS with the oldest and the newest Go
that `engines.go` allows (`>=1.22` → `1.22` and `>=1.22`):

1. installs gtr with `install.sh` / `install.ps1`;
2. `gtr ci` — exactly the versions of `gtr.lock` (commit it), failing if it is out of date;
3. `go vet ./...` through the `go` shim, so with the project's Go and `gtr_modules/`;
4. `gtr test --coverage`, failing below `test.coverage`.

Go itself is downloaded by gtr (`GTR_GO_VERSION` from the matrix); `actions/setup-go` is not
needed. `GITHUB_TOKEN` raises the GitHub API limit for git sources. Edit the file freely —
it is generated once.

### Secrets and private packages

```yaml
env:
  GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}        # this repository's token: public and own repos
  # GITHUB_TOKEN: ${{ secrets.PACKAGES_TOKEN }}    # a personal token for other private repositories
  GTR_REGISTRY: https://registry.example.com
  GTR_REGISTRY_TOKEN: ${{ secrets.GTR_REGISTRY_TOKEN }}   # from the registry's dashboard
```

### Publishing from CI

A workflow on tags that publishes the package (`gtr version patch && git push --follow-tags`
locally starts it):

```yaml
on:
  push:
    tags: ["v*"]
jobs:
  publish:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v5
      - run: |
          curl -fsSL https://raw.githubusercontent.com/shibisty/gtr/main/install.sh | GTR_NO_MODIFY_PATH=1 sh
          echo "$HOME/.gtr/bin" >> "$GITHUB_PATH"
      - run: gtr ci && gtr publish --registry ${{ vars.GTR_REGISTRY }}
        env:
          GTR_REGISTRY_TOKEN: ${{ secrets.GTR_REGISTRY_TOKEN }}
```

For a tool, build the archives and attach them to the release:

```yaml
      - run: gtr ci && gtr build --all-targets --archive
      - run: gh release create "$GITHUB_REF_NAME" build/*/*.zip build/*/*.tar.gz build/*/SHA256SUMS --generate-notes
        env:
          GH_TOKEN: ${{ github.token }}
```

(with `permissions: contents: write` on the job).

## Other CI systems

The same four commands work anywhere: install gtr with the installer, then `gtr ci`,
`go vet ./...` and `gtr test --coverage`. Cache `~/.gtr/store` and `~/.gtr/go` between runs
to skip downloads; `gtr ci --offline` then installs from the cache alone.

## Runner images

`ubuntu-latest`, `windows-latest` and `macos-latest` move to new system versions from time
to time. When a build breaks only after such a move, pin the previous image
(`ubuntu-24.04`) until the cause is fixed.
