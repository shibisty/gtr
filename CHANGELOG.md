# Changelog

## Unreleased

### Added
- `gtr mcp`: an MCP server on stdio for Claude Code and Claude Desktop (ADR-0011) — tools for
  packages (`list`, `why`, `outdated`, `add`, `remove`, `install`, `update`, `sync`, `link`),
  scripts, tests (results and coverage per package as JSON), builds, the registry and
  `publish` (a dry run without `--allow-publish`); resources `gtr://gtr.json`, `gtr://gtr.lock`,
  `gtr://schema`. Protocol revisions 2024-11-05 to 2025-11-25 (initialize) and 2026-07-28
  (stateless, `server/discover`). `gtr mcp --print-config` prints the client settings,
  `gtr mcp bundle` writes a Claude Desktop extension (.mcpb).
- A Claude Code plugin (`plugin/`, marketplace in `.claude-plugin/`): the `gtr mcp` server and
  a skill for gtr projects.
- The registry commands of gtr-manager are forwarded: `login`, `logout`, `whoami`, `search`,
  `info`, `yank`, `unyank`, `owner`.
- `schema/gtr.schema.json` accepts npm dependencies: `"preact": "npm:^10.19"`, scoped names like
  `@preact/signals`.
- In a project, a command gtr does not know goes to gtr-manager, which runs the script of that
  name (`gtr migrate` → `gtr run migrate`); elsewhere a mistyped command gets a suggestion
  (``unknown command "instal"; did you mean `gtr install`?``).
- `gtr env [--json] [NAME...]` — the Go, gtr-manager, paths and go environment that apply
  in a directory; installs nothing (missing versions are shown as `GTR_GO_REQUIRED`).
- `gtr doctor [--offline]` — checks the home directory, installed versions, the linked
  gtr-manager, `PATH` and shims, `GOROOT`/`GOTOOLCHAIN`/`GOPROXY` set in a way that breaks
  gtr, the project (versions, generated `go.mod`, `gtr_modules/`) and the network.
- `gtr self prune [--dry-run]` — removes downloaded archives, leftovers of interrupted
  installs and versions superseded by a newer patch; keeps the defaults and what the
  current directory uses.
- `gtr self list --remote [--all]` — versions available on go.dev and in gtr-manager releases.
- `gtr --go <version>` / `gtr --gtr <version>` before any command, like
  `GTR_GO_VERSION` / `GTR_MANAGER_VERSION`.
- `install.sh` and `install.ps1`: one-line installers (SHA-256 check, shims, `PATH`).
- `GTR_GO_MIRROR`: a mirror of go.dev/dl.
- Downloads of Go and releases resume after a dropped connection (Range requests, up to
  four attempts) and show progress on a terminal.
- `list`, `ls`, `why` and `outdated` are forwarded to gtr-manager.
- `build`, `dev`, `test`, `publish`, `link`, `unlink` and `version <bump>` are forwarded to
  gtr-manager (`gtr version` alone still prints gtr's version).
- gtr builds and releases itself: `gtr.json` with a `build` block; the release workflow
  runs `gtr-manager build --all-targets --archive` from the submodule (ADR-0010).
  `make build|all|release` do the same without gtr installed.
- ADR 0004, 0007 and 0008 accepted; ADR-0003 documents `gitlab:` and `git+` sources.
- ADR-0010 (build, test, release, links).

### Removed
- `build.sh`, `build.ps1`, `win.ps1` and `release.sh`: replaced by `gtr build`.

## 0.1.0 — 2026-10-09

### Added (stage 4)
- The `go` shim runs go in workspace mode when the nearest `go.work` was generated by gtr
  (ADR-0009): `GOWORK` set to it, `GOPROXY=off`, no `-mod=mod`.
- ADR-0009 (workspaces), Proposed.

### Added (stage 3, step 3)
- The `go` shim runs go with `GOPROXY=off`, `GOWORK=off` and `-mod=mod` (unless `GOFLAGS`
  sets `-mod`; `GOFLAGS` from `go env -w` is kept) when the go.mod go would use is the one
  gtr generated next to the nearest `gtr.json` (a nested module of its own is left alone), and
  adds gtr hints after go errors (`package X is not in std`, `no required module provides
  package`, …). Hints are skipped when stderr is a terminal and the command runs a
  program (`go run`, `go generate`, `go tool`).

### Added (stage 2, ADR-0008)
- Project commands (`new`, `init`, `install`, `uninstall`, `run`, `start`) are
  forwarded to gtr-manager, with the project's Go in `PATH`/`GOROOT` and
  `GOTOOLCHAIN=local`; the exit code is passed through.
- Go version per project from `engines.go` in the nearest `gtr.json` (also the legacy
  `engine` field), `GTR_GO_VERSION`, or the global default; missing versions are
  installed automatically. npm-style ranges: `1.26`, `^1.22`, `~1.26`, `>=1.26 <1.28`.
- gtr-manager versions: `self install gtr`, `engines.gtr`, `GTR_MANAGER_VERSION`,
  installed from GitHub releases verified against `SHA256SUMS`.
- `self link gtr <path>` / `self unlink gtr` — use a local gtr-manager build.
- `self use`, `self uninstall`, `self current` (which version applies here and why).
- `self shims` — `go`/`gofmt` in `~/.gtr/bin` that follow the project's Go version.
- `self update [version]` — gtr updates itself from its releases.
- `self install go` without a version installs what `gtr.json` requires.
- `release.sh` / `release.workflow.yml`; `GTR_GITHUB_API` + `GTR_GITHUB_TOKEN` for GitHub
  Enterprise or a mirror (`GITHUB_TOKEN` is sent only to api.github.com).
- Shims fall back to the system Go when no version is selected; Ctrl+C reaches the
  child, and a signal exit becomes 128+signal.

### Fixed
- Go versions installed as symlinks into `~/.gtr/go/` are recognized.

### Fixed
- `gtr self` without a subcommand and `gtr self install` without arguments panicked.
  Unknown subcommands were silently ignored; now they are usage errors (exit code 2).
- `self install go`:
  - `1` or `1.27` could select a release candidate; only stable releases are picked
    for partial versions, and `1.20` means the latest 1.20.x;
  - the SHA-256 from go.dev is verified, the HTTP status is checked (an error page was
    saved as the archive), requests time out;
  - archives with `../` paths (zip-slip) are rejected;
  - Go was installed into `./go` of the current folder; now `~/.gtr/go/<version>`
    (`GTR_HOME`, ADR-0005), unpacked through a temporary folder and moved in one
    rename, so a failed install leaves nothing behind;
  - errors are reported instead of panics.
- `version` was listed in help but disabled.
- `Makefile` used spaces instead of tabs; `build.ps1`/`win.ps1` left `GOOS`/`GOARCH`
  set in the console and ignored `go build` failures; `build.sh` used a different
  output layout than `build.ps1`.

### Added
- `self list [go|gtr]` lists installed versions (was a stub).
- gtr-manager as a git submodule (ADR-0006).
- Tests, CI workflow (`ci.workflow.yml`, move it to `.github/workflows/`), README.

### Changed
- Help lists only working commands; stage-2 commands (`self install gtr`, `self use`,
  `self update`) report that they are not implemented yet; project commands point to
  gtr-manager.
